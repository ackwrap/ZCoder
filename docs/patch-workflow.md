# 目录补丁工作流

## 目标与边界

日常在 `ZCode/` 直接开发，保留依赖、预览及所有 staged/unstaged/untracked 内容。补丁是基准分支固定提交到最终工作树的**完整目录差异**，不是按功能追加的提交序列。目录补丁必须整套应用，不能宣称各目录功能独立。

首次基准使用当前本地 `refs/heads/main` 的 `3c5b227649371507ddc4eb46ac5133afe6db1cab`；不创建/切换分支，不提交、推送或更新外层 gitlink。建议后续在独立开发分支工作，保留基准分支不动。基准引用与固定 SHA 由外层 `patches.config.json` 唯一拥有；引用漂移、HEAD 不包含基准或未解决冲突时停止，不自动 fetch/merge/rebase 或推断新基准。更换基准须显式修改配置并重新验收。

## 一键导出

`node scripts/export-patches.mjs` 从配置读取源码、基准和输出目录。`--source <目录>` 只覆盖本次源码目录；`--config <文件>` 用于显式配置；`--check` 生成并验证候选，但不替换补丁队列。

```text
源码最终工作树 → 独立临时 index（基准 + 最终文件）→ 不可变目标 tree
  → 按目录生成标准 Git binary/full-index diff → manifest + series
  → 独立 detached worktree 逐项 check --index / apply --index → 比较目标 tree
  → 再查源码/真实 index/基准/旧队列未变化 → 备份旧目录 → 发布新目录
```

- `packages/<包>`、`apps/<应用>` 各一组；其他目录按顶层分组，根文件合为 `root`。root 优先，其余按字典序，空组不输出；跨组重命名用删除/新增表达，避免跨目录重命名的隐含顺序依赖。
- 使用 Git 最终工作树语义合并暂存、未暂存和非忽略新增文件，保留删除、文件模式和二进制；不要求用户手工暂存新文件，不改变真实 index 的字节或暂存分层。会写入 Git 对象库及临时验证 worktree，因此 `--check` 不是“零磁盘写入”。
- 排除规则明确列在配置中，涵盖依赖、构建/声明输出、日志和缓存，**也作用于已跟踪文件**。被排除的改动保持原样，并在 manifest 列出路径。疑似凭据路径（如非示例 `.env`、私钥/凭据文件）拒绝导出，不读取其内容到补丁。新增嵌套 submodule gitlink 改动拒绝自动导出。
- 可选配置 `include` 是源码仓库根目录下的精确文件相对路径数组，按大小写精确匹配，不支持 glob、绝对路径、路径穿越或反斜杠。仅覆盖配置的 `exclude`，不递归包含目录；缺省或空数组保持原行为。硬性排除的 `.git`、`node_modules`，Git ignore、凭据检查、嵌套 gitlink 检查和基准/index/并发保护均不受影响。实际纳入的路径不列入 manifest 的 `excludedChangedPaths`。
- `include` 仅是选择机制，不代表来源、许可证或再分发授权已核实；任何文件导出前仍需独立确认。`packages/zcode-cua/helper/dist/windows-helper.js` 的来源及再分发许可尚未核实，本次仅配置预备收录，不导出或发布其内容。
- 标准补丁路径为 `a/packages/...`，不带 `ZCode/`。manifest 记录固定基准、源码 HEAD、目标 tree、各组路径及补丁 SHA-256；不写绝对本机路径、凭据或时间戳。相同源码状态重复导出内容一致。
- 校验 series 与 manifest 的顺序、名称、摘要；拒绝路径穿越、符号链接补丁和重复条目。逐补丁失败立即停止，不使用 `--reject`、跳过或修复后继续。
- 导出/准备源码共用外层排他锁；并发操作停止。源码文件、新增/删除列表、真实 index、HEAD、基准或旧输出在过程中变化，发布前停止，不覆盖后来的编辑。失败验证目录保留并报告；成功后只清理本工具创建的临时验证目录。
- 旧 `patches/` 整体移动到被 Git 忽略的 `.patch-backups/<唯一编号>/patches`，包含其中未提交文件。候选在同文件系统准备；发布失败则恢复原目录。进程在两次 rename 之间退出时，旧目录仍在备份，禁止自动清空或猜测恢复。
- 生成与重放只证明队列等于源码快照，不代替源码类型/Lint/受影响测试及交互 E2E。导出脚本不隐式运行应用构建或安装依赖。

## 启动与准备源码

`node scripts/prepare-patches.mjs` 校验配置、基准和队列完整性。工作树有改动（含已应用补丁）或 HEAD 已在基准之后：保留当前开发目录，**不应用、不撤回补丁**。仅当源码完全干净且 HEAD 等于固定基准时，先隔离校验整套队列，再按 series 逐项 `apply --check --index`、`apply --index`。失败立即停止，保留现状，不强制回滚。

`start-test.sh` 复用此入口，不再用“逐补丁能否反向应用”猜测已安装版本。`--check` 仍可能准备工具/依赖或首次应用补丁，并非只读检查。测试数据默认仍为 `.zcode-dev-data/`。

## 迁移与验收

迁移前保存外层/子模块状态、真实 index、staged/unstaged binary diff 和未跟踪列表；不撤回现有功能补丁。已验证的 Skills/MCP 工作以精确增量 `apply --check` 后应用到 `ZCode/`，不暂存，不改已有 staged 分层。随后从最终工作树导出整套目录队列。

外层工具用 Node 原生测试和临时 Git 仓库验证：稳定顺序、重复导出、已提交开发改动、暂存分层、新增/删除/跨目录重命名、二进制、模式、奇异文件名、已跟踪产物排除、凭据拒绝、基准漂移/不相干 HEAD/冲突、坏补丁/坏顺序失败停止、输出备份、并发锁及 dirty 启动保护。实际仓库另做完整队列重放并比较 tree。Windows 实跑；未运行的平台如实列出。
